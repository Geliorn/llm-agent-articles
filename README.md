# AI Article Writer (`llm-agent-articles`)

Контент-конвейер для WordPress: по заданной теме плагин предлагает список тем статей,
человек его согласовывает, дальше статьи выходят по расписанию — с SEO-структурой,
обложкой и мета-описанием, без ручного труда.

Полное ТЗ и обоснование решений: [`docs/article-writer-plan.md`](../../docs/article-writer-plan.md).

## Как это работает

1. **Контент-план** (`Контент-планы → Добавить план`) — тема направления, аудитория,
   тон, расписание, требования к статье и режим обложки.
2. **Предложить темы** — один запрос к модели, 20 тем с ключами и ракурсом,
   попадают в очередь со статусом «На согласовании».
3. **Очередь тем** — человек одобряет, правит формулировки, удаляет, добавляет свои
   (в том числе пачкой), меняет порядок. Порядок очереди = порядок публикации.
4. **Тик по расписанию** берёт первые одобренные темы и для каждой:
   план статьи → текст по разделам → сборка в блоки Gutenberg → перелинковка →
   чек-лист → обложка → публикация.

Темы, которые человек не одобрил, не публикуются никогда — кроме случая, когда в
плане явно включено автоодобрение.

## Что получается на выходе

Статья в блочной разметке (её можно править в редакторе как обычную):

- лид — прямой ответ на вопрос заголовка;
- блок «Коротко» (3–5 тезисов) и оглавление с якорями;
- 5–8 разделов H2, внутри — H3, абзацы по 2–4 предложения, списки, таблица, цитата;
- блок «Частые вопросы» — аккордеон (`core/details`, первый вопрос раскрыт) с разметкой
  FAQPage (раздел ниже);
- «Читайте также» — ссылки на соседние статьи плана, плюс ссылки в каталог по
  совпадению ключей с терминами;
- `post_excerpt`, meta title и meta description — в поля Yoast или Rank Math;
- автор — пользователь, указанный в плане (в кроне нет текущего пользователя, поэтому
  без этой настройки запись осталась бы без автора);
- обложка с подписью, `alt` проставлен.

Статья пишется **в два шага**: сначала модель отдаёт только план (строгий JSON),
затем текст каждого раздела отдельным запросом. Один запрос на всю статью упирается
в `max_tokens` и выдаёт простыню абзацев; шесть коротких запросов дают заявленный
объём и заданную структуру.

## Длина заголовков

Два отдельных предела, оба настраиваются:

| | По умолчанию | Куда идёт |
|---|---|---|
| Заголовок статьи (H1) | 250 символов | `post_title`, видим на странице |
| `meta_title` | 60 символов | поле SEO-плагина, видим в выдаче |

**Заголовок никогда не обрезается.** Если он не уложился в предел, плагин отдельным
коротким запросом просит модель переписать его короче, сохранив смысл и главный ключ.
Кандидат отбраковывается, если он всё ещё длиннее предела, стал бессмысленно коротким
или оказался префиксом исходного — то есть моделью тоже обрезан, а не переписан.
После исчерпания попыток (по умолчанию 2) заголовок остаётся полным, а в чек-лист
попадает замечание с причиной. Обрыва на полуслове не бывает ни в одной ветке.

Темы в очереди, заголовки разделов и вопросы FAQ не укорачиваются вовсе — только
нормализуются пробелы и снимаются кавычки.

## Чек-лист перед публикацией

После сборки считается отчёт (объём, число H2/H3, списки, таблицы, цитаты, длина
meta description, вхождение ключа, плотность ключа, перелинковка) и пишется в мету
`_laa_seo_report`. Если статья не прошла жёсткие минимумы (по умолчанию 700 слов и
3 раздела), она уходит в черновики, а не на сайт — это настраивается.

## Обложки

Три режима, переключаются глобально и на уровне плана.

> **Пропорции обложки должны совпадать с темой.** Если тема выводит миниатюру через
> `aspectRatio` (у `agent-catalog` на странице записи это `3/2`), браузер обрезает
> всё более широкое по бокам с `object-fit:cover` — и подпись у левого края исчезает.
> На 1200×630 при контейнере 3:2 срезается по 127 px с каждой стороны, то есть первая
> буква каждой строки. Поэтому дефолт пресета — 1200×800 (3:2); текущее соотношение
> показано рядом с полями размера на экране «Обложки», там же — какое использует тема.
> Перерисовать обложку уже опубликованной статьи: `wp laa recover <ID>`.

**Генерация** — Yandex ART (асинхронный, с опросом операции) или любой
OpenAI-совместимый `/v1/images/generations`. Промпт — шаблон с подстановками
`{title}`, `{theme}`, `{keywords}`. При ошибке можно откатиться на библиотеку.

**Библиотека + наложение** — картинка берётся из пула (список ID вложений, вложения
термина или папка внутри `uploads`; по кругу, случайно или по совпадению слов
заголовка) и прогоняется через пресет:

| Группа | Что настраивается |
|---|---|
| Полотно | размер, вписать/обрезать, фокальная точка, цвет фона, формат и качество |
| Фильтр | ч/б, яркость, контраст, размытие, тонирование цветом с силой |
| Слои | заливка цветом с прозрачностью, градиент (4 направления, цвет и прозрачность с каждого конца), полупрозрачная PNG-маска (растянуть / замостить / по центру), логотип, рамка со скруглением |
| Подпись | источник текста, шрифт, размер с автоподбором, интерлиньяж, максимум строк, ширина блока, позиция по сетке 3×3 с отступами, выравнивание, цвет, ПРОПИСНЫЕ, разрядка, тень, плашка под текстом |

Экран «Обложки» даёт **живой предпросмотр**: кнопка собирает картинку с текущими
(ещё не сохранёнными) значениями формы на реальной картинке из пула.

**Движок — только GD.** Imagick дал бы чуть более гладкие градиенты, но это две
полные реализации всего перечисленного и два набора багов; GD с FreeType есть на
всех хостингах сети. Единственный видимый компромисс — рамка рисуется прямой даже
при заданном скруглении углов.

**Шрифт.** GD нужен TTF/OTF; шрифты темы в формате woff2 не подходят. Порядок
поиска: шрифт пресета → путь из настроек → загруженный через экран «Обложки»
(`uploads/laa-fonts/`) → системный (DejaVu, Noto, Droid, Liberation). Не нашли —
картинка собирается без подписи, с предупреждением в админке.

## Инфографика

К статье можно собирать картинку с 6–8 тезисами — сетку блоков или нумерованный
список. Тезисы берутся отдельным коротким запросом из уже готового плана статьи,
рисуются тем же движком, что и обложки (GD).

**Куда ставится** (настройка «Куда ставить», глобально и в каждом контент-плане):

| Вариант | Что происходит |
|---|---|
| Обложкой (по умолчанию) | инфографика становится миниатюрой записи, обычная обложка не генерируется, в текст картинка не вставляется |
| В начале статьи | блок `core/image` сразу после лида — над «Коротко» и оглавлением; обложка делается как обычно |
| В конце статьи | блок `core/image` после «Частых вопросов» (дальше только «Читайте также»); обложка делается как обычно |

Включается глобально в настройках и переопределяется у каждого контент-плана.
Пресеты и живой предпросмотр — на экране «Инфографика». `wp laa infographic <ID>`
при варианте «Обложкой» сразу ставит картинку миниатюрой, при остальных — только
собирает её.

С 0.4.0 старые поля плана «Место в статье» и «ставить её же миниатюрой» заменены
этой настройкой; планы, где их меняли, получают значение «Как в настройках
плагина», то есть «Обложкой», пока его не поменять.

**Текст в картинке не индексируется**, поэтому тезисы остаются и в HTML: блок
«Коротко» никуда не девается, инфографика — визуальный дубль с осмысленным `alt`.
Польза здесь в репостах и мессенджерах, а не в поиске.

**Длина тезисов.** Кегль один на все пункты — подбирается по самому длинному
и опускается до минимума пресета. Что не влезло: сначала модель переписывает тезис
короче под измеренный бюджет символов, затем из макета выбрасывается целый пункт
(самый длинный первым), и только если пунктов осталось меньше трёх — инфографика
не делается. Обрезки текста на полуслове нет нигде.

**Пропорции.** Если инфографика ставится миниатюрой, её полотно должно совпадать
по пропорциям с тем, что выводит тема (у `agent-catalog` это 3:2) — иначе края
обрежет, как было с обложками. Дефолт 1200×800 это учитывает.

## Частые вопросы: аккордеон и разметка

Каждый вопрос — блок `core/details` с классом `laa-faq-item`: нативные
`<details>`/`<summary>`, без JS, первый раскрыт. Свёрнутые ответы остаются в HTML.
Стиль (+/× вместо треугольника, разделители) — `assets/css/faq.css`, подключается
только на страницах с таким FAQ. Перелинковка не ставит ссылки внутрь `<summary>` —
клик по вопросу должен раскрывать ответ, а не уводить со страницы.

**Разметка FAQPage** (`LAA_FAQ`) строится из текста записи при каждом показе, а не
из сохранённой копии: правки вопросов в редакторе попадают и в разметку. С Yoast
вопросы добавляются в его собственный граф (`wpseo_schema_graph`; WebPage
получает тип FAQPage — так же делает FAQ-блок самого Yoast), без Yoast выводится
отдельный `<script type="application/ld+json">`.

Касается только статей, написанных 0.4.0 и новее: у старых FAQ — заголовки H3 и
абзацы, они остаются как были, без аккордеона и без разметки.

Ожидания: с 2023 года Google показывает FAQ-сниппеты в выдаче почти только
государственным и медицинским сайтам. Разметка валидна и читается другими
поисковиками и ИИ-ассистентами, но раскрывающихся вопросов в выдаче Google, скорее
всего, не даст.

## Расписание

Как в `llm-agent-github-repos` — три равноправных триггера одного тика:

1. WP-Cron раз в 10 минут (по умолчанию, ничего настраивать не надо);
2. HTTP-эндпоинт за секретом: `curl "https://site/?articles_cron=СЕКРЕТ"`;
3. прямой PHP CLI: `php wp-content/plugins/llm-agent-articles/cron.php`.

Готовые команды — на экране настроек. Тик сам решает, каким планам пора: у каждого
свой интервал, окно времени и дни недели.

## WP-CLI

```
wp laa tick
wp laa run --plan=<id>
wp laa topics --plan=<id> [--count=30]
wp laa write --topic=<id>
wp laa list-topics [--plan=<id>] [--status=approved] [--limit=50]
wp laa preview-image [--preset=default] [--title="..."] [--out=/path/cover.jpg]
wp laa recover <ID>... [--preset=<id>]
```

## Куда публикуются статьи

В стандартные записи блога (`post`). Отдельного типа записи под статьи плагин не
заводит — блоговые шаблоны, ленты, рубрики и поиск уже работают для `post`.
Единственный CPT плагина — `laa_plan`, это сам контент-план, он непубличный.

В выпадающем списке плана есть ещё `page` (на случай иерархического раздела базы
знаний). Каталожные типы сети в список не попадают намеренно. Добавить свой тип
можно фильтром:

```php
add_filter( 'laa_target_post_type_choices', function ( $types ) {
	$types['lesson'] = 'Урок (lesson)';
	return $types;
} );
```

## Данные плагина

- CPT `laa_plan` — контент-планы (не публичный, только админка).
- Таблица `{prefix}laa_topics` — очередь тем.
- Опции `laa_settings`, `laa_image_presets`, `laa_log`, `laa_db_version`.
- Мета на созданной статье: `_laa_plan_id`, `_laa_topic_id`, `_laa_generated`,
  `_laa_provider`, `_laa_primary_keyword`, `_laa_seo_report`.

Деинсталляция удаляет таблицу и опции. Созданные записи и медиафайлы остаются —
это контент сайта, а не данные плагина.

## Требования

- WordPress 6.0+, PHP 7.4+ (проверено на 8.3). Для правки FAQ-аккордеона в редакторе
  нужен WordPress 6.3+ (блок `core/details`); на странице он работает на любой версии.
- Расширение GD с FreeType — для режима обложек «библиотека + наложение».
- Ключи доступа к одной из четырёх моделей: Yandex Foundation Models, DeepSeek,
  Timeweb TWC AI, OpenRouter.

## Безопасность

Нонсы на всех действиях админки и AJAX, `manage_options` на настройках и обложках,
`edit_posts` на очереди. HTTP-триггер — только по секрету, с троттлингом раз в
минуту. Ответ модели — недоверенные данные: он проходит через `wp_kses` по своему
белому списку, прежде чем попасть в запись. Папка-источник картинок проверяется на
выход за пределы `uploads`.
